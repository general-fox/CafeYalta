# Кафе «Ялта»

Адаптивный многостраничный интерфейс кафе в Москве: главная, меню доставки, корзина, оформление заказа, личный кабинет, программа лояльности и всплывающая форма бронирования. Основной цвет — `#334da0`, логотипы подготовлены без теней.

Это интерактивная демонстрационная версия. Меню, цены, адрес, телефон, время работы и условия доставки пока служат примерами. Заказы и брони **не отправляются в ресторан**. Деньги не списываются, SMS не отправляются, телефон не подтверждается. Профиль, корзина и история сохраняются в `localStorage` конкретного браузера: это не настоящая авторизация и не серверная база. Для проверки используйте вымышленные данные. Очистка данных сайта в браузере удаляет локальную историю.

## Локальный запуск

Нужны Node.js 22 и npm. Из папки проекта выполните:

```powershell
npm install
npm run dev
```

Откройте [http://localhost:5173](http://localhost:5173). Порт закреплён через `strictPort`: если 5173 занят, Vite сообщает об ошибке и не переключается незаметно на другой порт. Остановите прежний сервер или освободите порт, затем повторите запуск. Сервер слушает только локальный интерфейс.

```powershell
npm test
npm run build
npm run preview
```

- `npm test` запускает встроенные тесты Node.js: расчёт корзины, изменение количества и лимит порций, доставка, телефон и время бронирования по Москве.
- `npm run build` создаёт production-сборку в `dist`.
- `npm run preview` показывает готовую сборку по адресу [http://localhost:4173](http://localhost:4173); порт также фиксирован. Сначала выполните сборку.

## Проверка сценариев

1. На главной нажмите «Заказать доставку». Выберите категорию меню, откройте карточку блюда и добавьте его в корзину.
2. Измените количество в корзине. Для курьерской доставки минимум — 800 ₽, стоимость — 250 ₽, от 2 500 ₽ бесплатно; самовывоз без минимума и без платы за доставку. Эти условия демонстрационные.
3. Оформите тестовый заказ с вымышленными контактами. Откройте кабинет: там появятся состав, сумма и адрес, а также явная отметка тестового статуса.
4. Нажмите «Забронировать стол», выберите будущую дату и время. Тестовая заявка появится в разделе бронирований кабинета при входе с тем же телефоном.
5. Проверьте страницу лояльности. Инструкция адаптирована под «Ялту»; настоящая регистрация карты подключается после получения собственной ссылки поставщика карт.
6. Повторите сценарии на узком экране. На компьютере категории расположены слева, а на телефоне закреплены сверху и прокручиваются к выбранной категории; корзина доступна из закреплённой панели.

## Развёртывание на GitHub Pages

Репозиторий: [general-fox/CafeYalta](https://github.com/general-fox/CafeYalta).

1. Загрузите проект в ветку `main`, включая `package-lock.json` и `.github/workflows/deploy.yml`. Папки `node_modules`, `dist` и файлы секретов загружать не нужно.
2. В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
3. В **Actions** откройте workflow **Deploy to GitHub Pages**. Он запускается при обновлении `main`; также доступен ручной запуск **Run workflow**.
4. Workflow выполняет `npm ci`, `npm test`, `npm run build` и публикует `dist`. Дождитесь успешного задания `deploy`; фактическая ссылка будет в результате deployment.

Ожидаемый адрес после успешного развёртывания: [general-fox.github.io/CafeYalta/](https://general-fox.github.io/CafeYalta/). Этот README сам по себе не подтверждает, что публикация уже выполнена.

Сайт использует `HashRouter`, например `/#/delivery`, `/#/account`, `/#/loyalty`. Так переходы и перезагрузка внутренних страниц работают на статическом GitHub Pages без серверных правил маршрутизации. В Vite настроен относительный `base: './'`, поэтому ресурсы работают и из подпапки `CafeYalta`, и из корня собственного домена.

При переносе на собственный домен задайте его в **Settings → Pages → Custom domain**, настройте DNS у регистратора по [инструкции GitHub](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site) и включите HTTPS после проверки домена. Hash-маршруты можно оставить. Для чистых URL без `#` потребуется хостинг с перенаправлением запросов к приложению и соответствующая смена маршрутизатора.

## Подключение iiko и настоящий запуск

Пошаговая инструкция — [docs/IIKO_SETUP.md](docs/IIKO_SETUP.md). GitHub Pages обслуживает статические файлы; секреты и серверный API iiko должны работать на отдельном backend. Переменные `VITE_*` попадают в публичную сборку, поэтому ключи iiko в них хранить нельзя.

Для следующего этапа потребуются:

- Доступ к тестовому iikoWeb, `appId`, `clientSecret`, API-ключ предприятия и подготовленное внешнее меню. Секреты передаются через защищённое хранилище, не коммитятся в Git.
- Backend и база данных: синхронизация меню, цен, обязательных модификаторов и стоп-листов; проверка корзины и создание заказов на нужной кассе.
- Настоящее подтверждение телефона, серверные сессии и проверка принадлежности заказов пользователю.
- Получение реальных статусов iiko, защищённые webhooks и обработка ошибок/повторных запросов.
- Интеграция бронирования с залами и занятостью столов, собственная ссылка регистрации карты и утверждённые правила лояльности.
- Если нужна онлайн-оплата — отдельный платёжный провайдер с серверной проверкой платежа.
- Действующие контакты и условия доставки, собственные фотографии, реквизиты и утверждённые документы по работе с данными гостей.

После подключения каждую функцию переключаем с демонстрационных данных на проверенный серверный сценарий. Отметки деморежима убираются только тогда, когда соответствующая интеграция действительно работает.
